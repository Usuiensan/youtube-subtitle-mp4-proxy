# Proxmox 上の Ubuntu VM 運用手順

この手順は、Proxmox 上の Ubuntu VM で現在の YouTube 字幕焼き込み MP4/HLS proxy と Discord bot を動かし、Cloudflare Tunnel で `lab.usuiensan.dev` を公開する構成を対象にします。

## 構成

```text
Proxmox ホスト
└─ Ubuntu VM（cloud-init ではなく通常の永続 VM）
   ├─ FastAPI       127.0.0.1:8000
   ├─ Discord bot   FastAPI を内部URLで呼ぶ
   └─ cloudflared   Cloudflare Tunnel へ外向き接続

https://lab.usuiensan.dev
  ↓ Cloudflare Tunnel
http://127.0.0.1:8000（同じ Ubuntu VM）
```

Proxmox ホストやルーターで 8000 番ポートを公開しません。`cloudflared` は Ubuntu VM から Cloudflare へ外向き接続します。

この構成では Nginx は必須ではありません。Tunnel の Service URL を FastAPI に直接向けます。Discord bot の `/prepare` 呼び出しも Tunnel 経由にせず、`127.0.0.1:8000` を使います。

## 1. Proxmox と Ubuntu VM

Proxmox 側では次を確認します。

- VM の自動起動を有効にする
- ネットワークを `vmbr0` などのブリッジへ接続する
- Ubuntu VM に DHCP 固定割り当て、または固定IPを設定する
- 大きなキャッシュを置く場合は、SSD/HDDをVMへ常時マウントする
- GPUを使う場合は、GTX 1050 TiをVMへPCI passthroughできていることを確認する

GPU passthrough、NVENC、SSD/HDDの詳細は [Ubuntu 26.04 LTS + GTX 1050 Ti 運用手順](ubuntu-26.04-gtx1050ti-deploy.md)を参照してください。GPUがVMから見えない場合は、CPUエンコードで動かします。

Ubuntu VM内で確認します。

```bash
hostnamectl
ip -br address
df -h
nvidia-smi                  # GPUを使う場合だけ
```

## 2. Ubuntu のパッケージ

```bash
sudo apt update
sudo apt install -y \
  git curl ca-certificates \
  python3 python3-venv python3-pip \
  ffmpeg fonts-noto-cjk unzip
```

GPUを使う場合:

```bash
sudo apt install -y ubuntu-drivers-common
sudo ubuntu-drivers list --gpgpu
sudo ubuntu-drivers install --gpgpu
sudo reboot
```

確認:

```bash
ffmpeg -hide_banner -encoders | grep nvenc
nvidia-smi
```

`h264_nvenc` とGPUが確認できた場合だけ、後述の `FFMPEG_VIDEO_ENCODER=h264_nvenc` を使います。

yt-dlpのJavaScript runtimeを使う場合はDenoも入れます。

```bash
curl -fsSL https://deno.land/install.sh -o /tmp/deno-install.sh
sudo DENO_INSTALL=/usr/local sh /tmp/deno-install.sh
rm /tmp/deno-install.sh
deno --version
```

## 3. アプリの配置

```bash
sudo adduser --disabled-password --gecos "" app
sudo mkdir -p /opt/youtube-mp4-proxy
sudo chown -R app:app /opt/youtube-mp4-proxy

sudo -iu app
cd /opt/youtube-mp4-proxy
git clone YOUR_REPO_URL .
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m py_compile app/main.py app/settings.py bot/main.py
exit
```

更新済みのリポジトリを配置する場合は、cloneの代わりに次を使います。

```bash
cd /opt/youtube-mp4-proxy
git pull --ff-only
.venv/bin/pip install -r requirements.txt
```

## 4. キャッシュ領域

SSDを変換作業と直近キャッシュ、HDDをアーカイブにする場合の例です。実際のマウントポイントはVMのディスク構成に合わせて変更します。

```bash
sudo mkdir -p /mnt/ssd/youtube-mp4-hot
sudo mkdir -p /mnt/hdd/youtube-mp4-archive
sudo chown -R app:app /mnt/ssd/youtube-mp4-hot /mnt/hdd/youtube-mp4-archive
```

再起動後も必要なディスクはUUIDで `/etc/fstab` に登録し、次で確認します。

```bash
sudo mount -a
findmnt /mnt/ssd/youtube-mp4-hot
findmnt /mnt/hdd/youtube-mp4-archive
```

## 5. 共通環境ファイル

FastAPIとDiscord botの両方が同じ環境ファイルを読みます。特に `DISCORD_PREPARE_TOKEN` は両方で同じ値にします。値を変更したら、2サービスとも再起動が必要です。

```bash
sudo install -o app -g app -m 600 /dev/null /etc/youtube-mp4-proxy.env
sudo -u app nano /etc/youtube-mp4-proxy.env
```

最小構成:

```dotenv

# OpenAI互換の翻訳サーバーを使う場合だけ設定する。
```

## 6. systemd

FastAPI:

```bash
sudo tee /etc/systemd/system/youtube-mp4-proxy.service >/dev/null <<'EOF'
[Unit]
Description=YouTube subtitle burned MP4/HLS proxy
After=network-online.target
Wants=network-online.target

[Service]
User=app
Group=app
WorkingDirectory=/opt/youtube-mp4-proxy
EnvironmentFile=/etc/youtube-mp4-proxy.env
ExecStart=/opt/youtube-mp4-proxy/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --proxy-headers
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF
```

Discord bot:

```bash
sudo tee /etc/systemd/system/youtube-mp4-discord-bot.service >/dev/null <<'EOF'
[Unit]
Description=YouTube MP4 proxy Discord bot
After=network-online.target youtube-mp4-proxy.service
Wants=network-online.target

[Service]
User=app
Group=app
WorkingDirectory=/opt/youtube-mp4-proxy
EnvironmentFile=/etc/youtube-mp4-proxy.env
ExecStart=/opt/youtube-mp4-proxy/.venv/bin/python -m bot.main
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now youtube-mp4-proxy youtube-mp4-discord-bot
sudo systemctl status youtube-mp4-proxy youtube-mp4-discord-bot --no-pager
```

ローカル確認:

```bash
curl -fsS http://127.0.0.1:8000/healthz
sudo journalctl -u youtube-mp4-proxy -n 100 --no-pager
sudo journalctl -u youtube-mp4-discord-bot -n 100 --no-pager
```

## 7. Cloudflare Tunnel

`cloudflared` はProxmoxホストではなく、FastAPIと同じUbuntu VMへインストールします。以下はCloudflare Dashboardで管理するTunnelを使う手順です。

### Ubuntu VMへcloudflaredを入れる

Cloudflareのstable APT repositoryから `cloudflared` をインストールします。

```bash
sudo mkdir -p --mode=0755 /usr/share/keyrings
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg \
  | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null
echo 'deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared any main' \
  | sudo tee /etc/apt/sources.list.d/cloudflared.list
sudo apt update
sudo apt install -y cloudflared
```

バージョンを確認します。

```bash
cloudflared --version
```

### TunnelとPublic Hostname

Cloudflare Dashboardで次を設定します。

```text
Networking → Tunnels → 対象Tunnel
  → Routes → Add route → Published application

Hostname: lab.usuiensan.dev
Service:  http://127.0.0.1:8000
```

同じVM上のFastAPIへ接続するため、古いUbuntu VMのIPアドレスや停止済みVMのアドレスは指定しません。Cloudflare Tunnelのconnectorを入れ替える場合も、必ず現在のUbuntu VMで実行します。

Dashboardの「Install and Run」に表示されたTunnel tokenを、Ubuntu VMで実行します。tokenは秘密情報なので、リポジトリや `/etc/youtube-mp4-proxy.env` には保存しません。

```bash
sudo cloudflared service install '<TUNNEL_TOKEN_FROM_CLOUDFLARE>'
sudo systemctl enable --now cloudflared
sudo systemctl status cloudflared --no-pager
sudo journalctl -u cloudflared -n 100 --no-pager
```

DashboardのTunnel状態が `Healthy` になり、connectorの最終接続時刻が現在のVMになっていることを確認します。旧VMのconnectorが残っている場合は、停止または削除して、行き先を一つにします。

## 8. 外部確認

まずoriginを確認し、その後にCloudflare経由を確認します。

```bash
curl -i http://127.0.0.1:8000/healthz
curl -i https://lab.usuiensan.dev/healthz
```

両方ともHTTP 200なら、配信URLの確認:

```bash
curl -I https://lab.usuiensan.dev/youtube/VIDEO_ID/ja
curl -I https://lab.usuiensan.dev/youtube-hls/VIDEO_ID/ja
```

FastAPIの `/prepare` はDiscord botから内部URLへ呼びます。外部URLへprepare tokenを持ち出す必要はありません。

## 9. 502 / 503 の切り分け

### Cloudflareが502を返す

```bash
curl -i http://127.0.0.1:8000/healthz
sudo systemctl status cloudflared youtube-mp4-proxy --no-pager
sudo journalctl -u cloudflared -n 100 --no-pager
```

- ローカルも失敗: FastAPIまたはVM内のディスク・環境変数を直す
- ローカルは200、外部だけ502: TunnelのService URL、connector、Tunnel routeを直す
- TunnelはHealthyだが502: `cloudflared` が指定されたoriginへ接続できていない。`127.0.0.1:8000`、HTTP、ポート8000を確認する

### `/prepare` が503になる

FastAPIの `/prepare` は `DISCORD_PREPARE_TOKEN` が未設定だと503になります。`/etc/youtube-mp4-proxy.env` に設定し、両サービスを再起動します。

```bash
sudo grep -E '^(DISCORD_PREPARE_TOKEN|YOUTUBE_PROXY_INTERNAL_BASE_URL)=' /etc/youtube-mp4-proxy.env
sudo systemctl restart youtube-mp4-proxy youtube-mp4-discord-bot
```

### Discord botが起動しない

```bash
sudo journalctl -u youtube-mp4-discord-bot -n 100 --no-pager
```

`DISCORD_BOT_TOKEN`、`DISCORD_PREPARE_TOKEN`、Discord Developer Portalの招待権限を確認します。

## 10. 更新

```bash
cd /opt/youtube-mp4-proxy
sudo -u app git pull --ff-only
sudo -u app .venv/bin/pip install -r requirements.txt
sudo systemctl restart youtube-mp4-proxy youtube-mp4-discord-bot
curl -fsS http://127.0.0.1:8000/healthz
```

Proxmox VMのスナップショットやバックアップを取る場合は、更新前に実行します。キャッシュは再生成できますが、設定ファイルとTunnel tokenはバックアップへ平文で含めないでください。
